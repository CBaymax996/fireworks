# AGENTS.md

## Project Overview

Fireworks is a Gradle multi-module project with two submodules:

- **fireworks-server**: Kotlin + Spring Boot 4.0 backend with SQLite
- **fireworks-web**: Vue 3 + Vite + TypeScript frontend

## Prerequisites

- JDK 25
- Node.js >= 22

## Development Commands

### Backend (fireworks-server)

```bash
./gradlew :fireworks-server:bootRun          # Start backend server (port 8080)
./gradlew :fireworks-server:test            # Run backend tests
./gradlew :fireworks-server:compileKotlin   # Compile Kotlin only
```

Backend uses SQLite database at `./fireworks.db` (or `./fireworks-test.db` in dev profile).

### Frontend (fireworks-web)

```bash
cd fireworks-web
npm install                    # Install dependencies
npm run dev                    # Start dev server (port 5173, proxies /api and /graphql to backend)
npm run build                  # Production build (type-check + vite build)
npm run test:unit              # Unit tests with Vitest
npm run test:e2e               # E2E tests with Playwright (requires `npx playwright install` first)
npm run lint                   # Lint: oxlint then eslint with --fix
npm run format                 # Format with prettier
```

### Full Stack

Start both backend and frontend separately. Frontend dev server proxies API calls to backend on port 8080.

## Architecture

### Backend (Kotlin)

Package structure under `site.hanabii.fireworks`:

- `app/` — Controllers and GraphQL resolvers (AuthController, GraphQL Query/Mutation classes)
- `domain/` — Domain models and repository interfaces
- `infra/` — Repository implementations, database config, Ktorm ORM setup
- `infra/_config/` — Spring config (GraphQL, Ktorm, schema init, tracing)

API Layer:
- **GraphQL** (primary): Schema generated by `graphql-kotlin-schema-generator`, served via Spring for GraphQL at `/graphql`
- **REST**: Auth endpoints at `/api` (AuthController)
- GraphQL resolvers: Auth, Vault, Portfolio, FamilyTree (both Query and Mutation)

Database: SQLite with Ktorm ORM, schema auto-initialized on startup (`fireworks.db.init-schema=true`).

### Frontend (Vue 3)

- `src/api/` — REST API clients (axios)
- `src/graphql/` — GraphQL queries/mutations (paired `.gql` + `.ts` files)
- `src/stores/` — Pinia stores (auth, vault, familyTree, counter)
- `src/views/` — Page components
- `src/components/` — Reusable components (sky weather effects, etc.)
- `src/composables/` — Vue composables

## Code Style

- **Prettier**: no semicolons, single quotes, print width 100
- **EditorConfig**: 2-space indent, LF line endings
- **Lint pipeline**: `npm run lint` runs oxlint first, then eslint
- **Type checking**: `vue-tsc --build` (not plain `tsc`)

## Testing

- Backend: JUnit 5 + Spring Boot Test + Mockito-Kotlin. Tests use separate `fireworks-test.db`.
- Frontend unit: Vitest with jsdom environment, tests in `src/components/__tests__/`
- Frontend e2e: Playwright, tests in `e2e/`, runs against dev server

## Key Quirks

- Backend `application.properties` contains a tushare API token — do not commit new secrets
- GraphQL schema is code-generated at runtime (no static `.graphql` schema file on backend)
- Frontend Vite config allows cloudflared tunnel hosts and proxies `/api` + `/graphql` to localhost:8080
- Gradle wrapper version: 9.5.1
- Maven repositories use Aliyun mirrors (China) as primary, Maven Central as fallback

## Git Rules

When AI agent creates commits, it MUST use its own agent name as the author, NOT the user's identity:

```bash
git commit --author="mimocode <mimocode@users.noreply.github.com>" -m "commit message"
```

This ensures git history clearly distinguishes between human commits and AI-generated commits.
